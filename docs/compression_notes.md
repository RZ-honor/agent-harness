# 观测压缩设计笔记

## 为什么必须做证据压缩

工具型 Agent 的观测膨胀主要来自日志类工具：单次返回可达上万字符，若不压缩，
三轮调用就能吃掉整个上下文窗口。观测压缩的目标不是节省而节省，而是在节省
token 的同时保住下游判定所需的证据行。这是本仓库证据压缩模块的第一设计约束。

## 行级显著性两轮选行

第一代实现按关键词窗口截取，实测发现两个问题：窗口边界会切断完整语义行；
关键词表若包含任务模板词，会把预算耗在与证据无关的套话上。第二代改为行级
显著性打分，分两轮选行：第一轮只保留强信号行（异常、超时、错误码、指标峰值），
第二轮在剩余预算内补充弱信号行（时间戳、服务名、上下文衔接）。两轮之后仍有
超预算内容，则对单行做字符窗口截断并显式标注省略。

## 节省率与工作点

在排障沙箱上扫描六档压缩率，观测保留 33% 时 token 节省 63% 而任务成功率无损；
保留率跌破 10% 后成功率显著下滑。节省率不是越高越好，工作点必须留在悬崖之前，
并为随机扰动留出安全边界——这是证据压缩实验给出的核心结论。

## 锚点丢失的口径

压缩的代价用"金标锚点丢失率"度量：预先声明每个案例的必见证据行，压缩后统计
仍可见的比例。锚点丢失率被固化为回归门限，任何压缩器改动都必须先过这条线，
再谈节省率提升。节省与保真是同一枚硬币的两面，度量口径必须先于优化存在。
