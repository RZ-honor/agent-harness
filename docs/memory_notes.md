# 记忆分层设计笔记

## 短期：假设排除

多步排障中，被否定的根因假设必须留在短期记忆里，下一跳取证前先行排除，
否则策略代理会在两个候选根因之间来回摆动。摆动次数与步数浪费由 metrics
脚本测量。

## 长期：故障模式索引

跨案例沉淀的长期记忆按故障类型索引：命中过的根因-证据形态在同类告警下
优先验证。长期记忆只影响验证顺序，不跳过取证步骤——这是防止记忆退化为
"背答案"的硬约束。

## 幂等与重复拦截

读工具不缓存（避免过期数据），写工具按幂等键去重。并发下同键只允许一次
副作用：纯结果缓存挡不住并发窗口，必须做 in-flight 单飞占位。重复查询拦截
的净收益（80 次降到 25 次）由 metrics 脚本在固定场景上复现。
