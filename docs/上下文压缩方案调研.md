# 上下文压缩方案调研与本项目定位

> 用途：为本仓库的观测压缩（ObservationCompressor）选型与后续迭代提供依据。
> 资料来源：博查检索命中的公开文章与各项目官方仓库（以仓库/官方文档为准，未逐篇精读的结论已标注）。
> 日期：2026-10-22

## 一、开源界的三条技术路线

### 1. Token 级压缩（LLMLingua 系列，微软）

- 思路：用小模型给 token 打重要性分数，删掉低信息量 token；LLMLingua-2 改为任务无关的 token 分类器；官方宣称最高约 20× 压缩。
- 优点：压缩率极高，对"提示词冗余"型输入效果好。
- 代价：**不可逐字回溯**——压缩后的文本不再是原文子串，Agent 的引用校验（本仓库的结论门禁）会失效；需要额外小模型，离线确定性被破坏。
- 本项目结论：**不采用**。理由是项目约束"结论必须逐字可引用原文"，token 级改写直接违背该约束。

### 2. LLM 摘要压缩（Claude Code autoCompact、OpenHands Condenser 家族）

- Claude Code：上下文接近上限时（公开分析文章称约 92% 阈值）调用模型把历史压成摘要，可用 `/compact` 手动触发；有源码分析文章称摘要压缩率约 1:5。
- OpenHands：`Condenser` 抽象，含 `RecentEventsCondenser`（只留最近事件）、`LLMSummarizingCondenser`（LLM 摘要）、`ObservationMaskingCondenser`（把旧观测替换为占位符）、`LLMAttentionCondenser`（按注意力保留重要事件）等实现。
- 优点：语义保真度高，长历史可用。
- 代价：**不可复现、成本高、有信息损失且损失不可定位**；离线与确定性验证不成立。
- 本项目结论：**列为兜底档**（极端超预算时可用），不进主链路；主链路要求确定性可复现。

### 3. 结构化选择（本仓库路线，SWE-agent 等同类）

- SWE-agent 等编码 Agent 采用"观测截断 + 结构保留"的确定性做法；本仓库在此基础上做了行级显著性两轮选行、首行结构保留、显式省略标记。
- 优点：**逐字可回溯、零模型调用、结果确定可复现**（`test_determinism.py` 锁死）。
- 代价：词表/规则与域绑定——这正是真实数据验证暴露的问题（见下节）。

## 二、真实数据验证暴露的域错配与修复

用真实编码 Agent 会话（365 条工具输出、44.8 万字符）复测：

| 策略（50% 预算） | 证据存活 | 退出码 | file:line | 错误行 | 测试汇总 | 完全可用 |
|---|---|---|---|---|---|---|
| 运维词表（v1） | 8.8% | 0% | 37.5% | 30.9% | 18.6% | 10.6% |
| 头截断 | 36.8% | 100% | 64.3% | 78.2% | 7.0% | 58.8% |
| 头尾截断 | 53.6% | 100% | 78.6% | 67.3% | 95.3% | 71.8% |
| **编码词表（v2）** | **91.7%** | **100%** | **92.9%** | **94.5%** | **100%** | **92.9%** |

根因：v1 词表按运维日志调参且区分大小写，对编码输出（`failed`/`✗`/`Traceback`/`exit code 1`）命中率仅 1.4%。

v2 修复：`profile='coding'`（大小写不敏感词表 + file:line/栈帧/diff/测试汇总/退出码结构锚点 + 尾部位置加权）；`profile='auto'` 按内容自动判别，实测与 coding 档持平（91.2%）。运维档 `profile='ops'` 保持原行为，合成沙箱全部数字不变。

## 三、下一阶段可用性判定（本仓库新增口径）

"压缩后还能不能被下一跳模型使用"，用四类锚点是否幸存判定：退出码、file:line 定位、首条错误行、测试汇总计数；四类全存活记为"完全可用"。

- 50% 预算：v2 完全可用 **92.9%**（头尾截断 71.8%）
- 20% 预算：v2 完全可用 **74.1%**（头尾截断 45.9%）
- 10% 预算：v2 完全可用 **64.7%**（头尾截断 36.5%）

## 四、后续可借鉴的优化方向（按性价比排序）

1. **观测用后即清（tool result clearing）**：Anthropic 上下文工程文章提到，工具结果被用过之后可从上下文清除，只留摘要引用——比压缩更彻底，且不损失"已消费"信息的价值。
2. **域自适应词表扩展**：把 v2 的 coding 档做成"词表插件 + 自动判别"，新增域（运维、数据、前端）各自一份，用真实会话回归（本仓库 `realdata` 脚本即验证管线）。
3. **重要事件 pin + 分层保留**：借鉴 OpenHands `LLMAttentionCondenser` 的思路，但保持确定性——用规则给"已产生结论依赖的事件"打 pin，其余可忘。
4. **LLM 摘要只做兜底**：仅在超预算且规则档证据存活率低于阈值时触发，并强制保留原文引用块，避免不可回溯。
5. **压缩质量自检**：压缩后按"锚点探测"（本仓库 `anchors_of`）自检，低于阈值则回退到更高保留档——把"压缩是否可用"变成运行时可判定条件。

## 五、本项目取舍总结

| 维度 | LLMLingua | LLM 摘要 | 头尾截断 | 本仓库 v2 |
|---|---|---|---|---|
| 压缩率 | 最高 | 中 | 中 | 中高 |
| 逐字可回溯 | ✗ | ✗ | 部分 | ✓ |
| 确定性可复现 | 小模型固定则可 | ✗ | ✓ | ✓ |
| 零额外成本 | ✗ | ✗ | ✓ | ✓ |
| 真实数据证据存活 | 未测 | 未测 | 53.6% | **91.7%** |

结论：在"必须可回溯 + 必须可复现 + 零成本"的约束下，规则档 + 域自适应是当前最优点；LLM 摘要保留为超预算兜底，不做主链路。
